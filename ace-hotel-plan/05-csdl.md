# 05. Cơ sở dữ liệu

Nguồn: `chot-pham-vi-actor-usecase-bang.md` mục 4 [CHỐT] — **8 bảng**, tên tiếng Anh dạng snake_case. Khoa viết `schema.sql` và `sample-data.sql` trong Tuần 1; ERD và từ điển dữ liệu đưa cho cả nhóm cuối Tuần 1 (tên các bảng chính đưa ngay đầu tuần).

## 1. Bảng và quan hệ [CHỐT]

| Bảng | Cột chính | Khóa ngoại |
|---|---|---|
| `users` | user_id (PK), username, password_hash, full_name, role | |
| `room_types` | room_type_id (PK), name, price_per_night, capacity, description | |
| `rooms` | room_id (PK), room_number, floor, status | room_type_id → room_types |
| `customers` | customer_id (PK), full_name, phone, id_number, email | |
| `bookings` | booking_id (PK), check_in_date, check_out_date, actual_check_in, actual_check_out, status, created_at | customer_id → customers; room_id → rooms; created_by → users |
| `services` | service_id (PK), name, unit_price, unit | |
| `service_orders` | order_id (PK), quantity, unit_price, ordered_at | booking_id → bookings; service_id → services |
| `invoices` | invoice_id (PK), room_charge, service_charge, total, payment_method, paid_at | booking_id → bookings (1 – 1); created_by → users |

Quan hệ: room_types 1–N rooms; customers 1–N bookings; rooms 1–N bookings; bookings 1–N service_orders; services 1–N service_orders; bookings 1–1 invoices; users 1–N bookings và users 1–N invoices.

Giá trị trạng thái [CHỐT]:
- `rooms.status`: AVAILABLE, OCCUPIED, MAINTENANCE
- `bookings.status`: BOOKED, CHECKED_IN, CHECKED_OUT, CANCELLED
- `users.role`: RECEPTIONIST, MANAGER

## 2. DDL nháp cho H2 [ĐỀ XUẤT]

Kiểu dữ liệu, ràng buộc CHECK, chỉ mục và giá trị của `payment_method` là phần mình thêm; tên bảng, cột, khóa theo file chốt. Tiền VND lưu số nguyên (`BIGINT`) để khỏi lỗi làm tròn.

```sql
CREATE TABLE IF NOT EXISTS users (
  user_id       BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  username      VARCHAR(50)  NOT NULL UNIQUE,
  password_hash VARCHAR(100) NOT NULL,
  full_name     VARCHAR(100) NOT NULL,
  role          VARCHAR(20)  NOT NULL CHECK (role IN ('RECEPTIONIST','MANAGER'))
);

CREATE TABLE IF NOT EXISTS room_types (
  room_type_id    BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name            VARCHAR(50)  NOT NULL UNIQUE,
  price_per_night BIGINT       NOT NULL CHECK (price_per_night > 0),
  capacity        INT          NOT NULL CHECK (capacity >= 1),
  description     VARCHAR(500)
);

CREATE TABLE IF NOT EXISTS rooms (
  room_id      BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  room_number  VARCHAR(10) NOT NULL UNIQUE,
  floor        INT         NOT NULL CHECK (floor >= 0),
  status       VARCHAR(20) NOT NULL DEFAULT 'AVAILABLE'
               CHECK (status IN ('AVAILABLE','OCCUPIED','MAINTENANCE')),
  room_type_id BIGINT      NOT NULL REFERENCES room_types(room_type_id)
);

CREATE TABLE IF NOT EXISTS customers (
  customer_id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  full_name   VARCHAR(100) NOT NULL,
  phone       VARCHAR(20)  NOT NULL,
  id_number   VARCHAR(30),
  email       VARCHAR(100)
);

CREATE TABLE IF NOT EXISTS bookings (
  booking_id       BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  customer_id      BIGINT      NOT NULL REFERENCES customers(customer_id),
  room_id          BIGINT      NOT NULL REFERENCES rooms(room_id),
  check_in_date    DATE        NOT NULL,
  check_out_date   DATE        NOT NULL,
  actual_check_in  TIMESTAMP,
  actual_check_out TIMESTAMP,
  status           VARCHAR(20) NOT NULL DEFAULT 'BOOKED'
                   CHECK (status IN ('BOOKED','CHECKED_IN','CHECKED_OUT','CANCELLED')),
  created_at       TIMESTAMP   NOT NULL DEFAULT CURRENT_TIMESTAMP,
  created_by       BIGINT      NOT NULL REFERENCES users(user_id),
  CHECK (check_out_date > check_in_date)
);
CREATE INDEX IF NOT EXISTS idx_bookings_room_dates
  ON bookings(room_id, check_in_date, check_out_date);

CREATE TABLE IF NOT EXISTS services (
  service_id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name       VARCHAR(100) NOT NULL UNIQUE,
  unit_price BIGINT       NOT NULL CHECK (unit_price >= 0),
  unit       VARCHAR(30)  NOT NULL
);

CREATE TABLE IF NOT EXISTS service_orders (
  order_id   BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  booking_id BIGINT    NOT NULL REFERENCES bookings(booking_id),
  service_id BIGINT    NOT NULL REFERENCES services(service_id),
  quantity   INT       NOT NULL CHECK (quantity >= 1),
  unit_price BIGINT    NOT NULL CHECK (unit_price >= 0),   -- sao chép giá lúc dùng
  ordered_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE IF NOT EXISTS invoices (
  invoice_id     BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  booking_id     BIGINT      NOT NULL UNIQUE REFERENCES bookings(booking_id),
  room_charge    BIGINT      NOT NULL CHECK (room_charge >= 0),
  service_charge BIGINT      NOT NULL CHECK (service_charge >= 0),
  total          BIGINT      NOT NULL,
  payment_method VARCHAR(20) NOT NULL CHECK (payment_method IN ('CASH','CARD','TRANSFER')),
  paid_at        TIMESTAMP   NOT NULL,
  created_by     BIGINT      NOT NULL REFERENCES users(user_id),
  CHECK (total = room_charge + service_charge)
);
```

Lưu ý khi chạy thật: kiểm tra từ khóa của H2 với tên cột như `floor`, `role`, `name`, `unit` (nếu báo lỗi thì đặt trong dấu nháy kép hoặc đổi tên và cập nhật từ điển dữ liệu).

## 3. Truy vấn phòng trống [ĐỀ XUẤT]

Khoảng ngày được hiểu là nửa mở `[ngày nhận, ngày trả)`: ngày trả của đặt phòng này có thể là ngày nhận của đặt phòng kế tiếp.

```sql
SELECT r.*
FROM rooms r
WHERE r.status <> 'MAINTENANCE'
  AND (:typeId IS NULL OR r.room_type_id = :typeId)
  AND NOT EXISTS (
    SELECT 1 FROM bookings b
    WHERE b.room_id = r.room_id
      AND b.status IN ('BOOKED','CHECKED_IN')
      AND b.check_in_date  < :checkOut
      AND b.check_out_date > :checkIn
  );
```

Hai điểm cần nhóm xác nhận: nửa mở và việc không tính CHECKED_OUT vào trùng lịch (`10-cau-hoi-mo.md`, mục 2).

## 4. Tính tiền [ĐỀ XUẤT]

- `nights = max(1, check_out_date − check_in_date)` (tính theo ngày đã đặt; xem file 10 mục 1)
- `room_charge = nights × room_types.price_per_night`
- `service_charge = Σ (service_orders.quantity × service_orders.unit_price)` của đặt phòng đó
- `total = room_charge + service_charge`

## 5. Kế hoạch dữ liệu mẫu (`sample-data.sql`)

Mục tiêu trong Tuần 1 của Khoa: khoảng **10 phòng, 5 loại phòng, 10 khách, vài dịch vụ** [CHỐT]. Phần cụ thể dưới đây là [ĐỀ XUẤT].

| Bảng | Số dòng | Gợi ý |
|---|---|---|
| users | 2 | `letan`, `quanly` (mật khẩu băm BCrypt) |
| room_types | 5 | Standard, Superior, Deluxe, Family, Suite; giá mẫu: Standard 780.000đ, Deluxe 1.250.000đ, Suite 3.200.000đ (khớp hình mẫu), hai loại còn lại tự đặt |
| rooms | 10 | Trải trên 4 tầng; có 301 (Deluxe), 205 (Standard), 418 (Suite), 102 (Standard) cho khớp hình mẫu; một phòng ở trạng thái MAINTENANCE |
| customers | 10 | Gồm Nguyễn Minh Anh, Trần Quốc Bảo, Lê Thu Hà, Phạm Gia Huy (hình mẫu) và 6 tên khác |
| services | 6 | Ăn sáng, Đưa đón, Giặt ủi, Spa, Thuê xe, Nước uống |
| bookings | khoảng 12 | Phủ đủ các trạng thái và tình huống ở bảng dưới |
| service_orders | 5 đến 8 | Gắn với các đặt phòng đang ở và đã trả |
| invoices | 3 đến 4 | Cho các đặt phòng CHECKED_OUT; số tiền khớp công thức |

**Dùng ngày tương đối** (`DATEADD('DAY', n, CURRENT_DATE)`) để dữ liệu mẫu luôn "hôm nay" đúng vào ngày demo.

| Tình huống | Ngày (so với hôm nay) | Trạng thái |
|---|---|---|
| Đang ở, nhận hôm nay, chưa đến hạn | 0 → +2 | CHECKED_IN |
| Đặt rồi, nhận hôm nay (để demo check-in) | 0 → +1 | BOOKED |
| Quá hạn trả phòng | −3 → −1 | CHECKED_IN |
| Đặt rồi, nhận ngày mai | +1 → +3 | BOOKED |
| Chồng lịch với một đặt phòng khác (để demo bị từ chối) | trong khoảng +1 → +3 cùng phòng | (thử đặt lúc demo) |
| Đã trả phòng, có hóa đơn | −10 → −7 và −6 → −4 | CHECKED_OUT |
| Đã hủy | +5 → +7 | CANCELLED |

`sample-data.sql` phải **chạy lại được nhiều lần** (xóa sạch rồi nạp) để "nạp lại dữ liệu mẫu sạch" trước buổi demo (Tuần 4).

## 6. Kiểm tra toàn vẹn (NFR-04)

- Khóa chính, khóa ngoại, CHECK như trên; không xóa phòng hoặc khách hàng đang có đặt phòng (kiểm tra thêm ở tầng service để báo lỗi tiếng Việt).
- Không đặt trùng lịch: kiểm tra ở service trong giao dịch (CSDL không tự chặn được khoảng ngày chồng nhau).
